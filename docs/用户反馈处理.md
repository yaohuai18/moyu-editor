# 用户反馈处理

> 这份文档回答：**用户来找你（而不是找代码）的时候，怎么办。**
> 原则：先让用户安心，再查问题；数据安全永远排在修 bug 前面。

## 一、收到反馈先分类

| 类型 | 特征 | 第一反应 |
| --- | --- | --- |
| 报错 | 「保存失败」「AI 报错」 | 要时间点 + 用户账号，去 `ops:daily` / 日志里按编号查 |
| 数据丢失 | 「我写的没了」 | **最高优先级**，按第二节处理 |
| 功能建议 | 「能不能加导出」 | 记进 [产品迭代优先级](产品迭代优先级.md)，不当场承诺时间 |
| 内容安全 | 有人写违规内容 | 按隐私政策处理，不扩散、不截图外传 |
| 投诉/退款 | 「扣了我额度但没结果」 | 查 `ops:ai` 该用户记录，确属失败就补次数（口头说明即可，现在没有自动补偿） |

## 二、「我写的没了」处理流程

1. **别让用户继续操作**（刷新、切章都可能把能恢复的东西冲掉）
2. 让用户别关页面，先问：编辑器底部状态灯最后显示什么？
3. 你这边跑：
   - `npm run ops:db` 看孤立数据和完整性
   - `npm run db:studio` 查该用户章节的 `Revision` 记录 ——
     只要保存过（哪怕自动保存），版本历史里就有
4. 能找到版本 → 让用户在编辑页「版本历史」里回滚，或者你直接告诉他哪条
5. 版本里也没有 → 内容确实没落过盘（比如断网状态写完直接关页面），如实道歉，
   说明「断网时写的内容需要网络恢复后手动点一次保存」

**给用户回话时的事实边界**：能恢复就说哪一条、怎么恢复；不能恢复就说清楚
为什么（没保存过 ≠ 保存了又丢），不要含糊「帮你看看」然后消失。

## 三、用户要删自己的数据

- 用户自己能做的（已经上线）：删除章节、删除作品、注销账号（全部级联删干净）
- 需要你代做的：用户说「把我所有数据彻底删掉」→ 引导他用「账号设置 → 注销」，
  注销会连作品、章节、版本、人物卡、风格档案、AI 台账的关联一起删
  （AI 台账里的 userId 关联删，但用量统计保留匿名计数 —— 这是成本记账，见隐私政策）
- **永远不要**手动去数据库里删用户行 —— 级联关系复杂，用界面或脚本
  （`npm run works:move` 可先把作品转给别的账号再注销）

## 四、反馈的固定回复套路

不管多急，先回这三句：

1. 「收到，我在查」—— 用户最怕的是没人理
2. 「你现在先别刷新那个页面」（数据类问题）
3. 查完如实说：是 bug（什么时候修）/ 不是 bug（怎么用）/ 数据能/不能恢复（为什么）

## 五、把反馈变成改进

每条处理完的反馈，花 10 秒归档到 [产品迭代优先级](产品迭代优先级.md)：
- 报错类 → 对应已知问题还是新问题？新的要记
- 建议类 → 加进 backlog，标「来自用户」—— 用户提的需求比想象中的重要
- 同一类问题出现 3 次 → 不管多小都要排进下一版（说明设计有问题，不是用户笨）
