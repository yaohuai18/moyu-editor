# 已知问题

**这份清单的作用是让你心里有数**，不是让你难堪。
别人问"这个能做吗"，你能立刻答"现在不行，为什么不行，什么时候能做"，
比含糊地说"应该可以吧"专业得多。

分三档：🔴 影响使用（要知道）｜🟡 功能缺失（有意没做）｜⚪ 工程债（以后要还）

---

## 🔴 影响使用的

### 1. 单章超过 5 万字时，AI 功能用不了

AI 一次最多处理 5 万字（去空白后）。超了会返回明确提示，
让你分章或分段处理。

**为什么**：模型单次窗口有限，硬塞进去只会让结果变差或直接失败。
**计划**：长章节自动分段 + 排队处理。

### 2. 版本历史只增不减，数据库会一直变大

每次保存留一条版本记录，**数据库里是全量保留的**，界面只是分页显示。
一个人写 100 万字、每天保存 50 次，`Revision` 表会很大。

**为什么**：这是刻意的取舍 —— 版本历史是"写错了能退回去"的唯一兜底，
早期删掉等于在最需要它的时候没有。
**代价**：数据库体积增长快，备份文件也会变大。
**计划**：加清理策略（比如只保留最近 90 天 + 每次会话首末版本）。
真要清理时先备份。

### 3. 忘记密码没有自助找回

没有接邮件发送服务，所以做不了"点链接重置密码"。
现在忘记密码只能联系运营者，在服务器上手动改（改法见 [部署说明](部署说明.md)）。

**为什么**：发邮件要配 SMTP 或第三方邮件服务，属于额外的基础设施。
**计划**：接邮件服务后加"忘记密码"和"邮箱验证"。

### 4. AI 的每分钟限流在多实例部署下会失效

「每人每分钟 10 次」的计数在**进程内存**里（`src/lib/rate-limit.ts`）。
单实例完全有效；跑两个以上实例时，每个实例各算各的，等于限流失效。

**不受影响的**：每日 30 次额度（它是查数据库算的，多实例也准）。
**计划**：多实例部署前必须先换 Redis（代码里标了位置）。

## 🟡 功能缺失（有意没做）

### 5. 编辑器是纯文本，不是富文本

没有加粗、斜体、标题级别、居中这些排版功能。
**为什么**：当前用**受控 textarea**，正文进 AI 出 AI 最干净；
上富文本编辑器就要在 AI 前后做 HTML 转换，容易出脏数据。
**计划**：真需要排版时换成 Tiptap（页面里已经隔离成独立区块，替换成本可控）。

### 6. 人物卡和「禁用词」界面上还不能编辑

编辑页右侧能看到人物卡和禁用词的**内容**，但改不了。
作品设置页能改风格档案的语气 / 视角 / 句式，`description` 和 `forbiddenWords`
两个字段暂时没有输入框（接口入参里也没有，所以保存时不会被清空，是安全的）。

**计划**：人物卡可视化编辑 + 禁用词编辑，排在后面的阶段。

### 7. ~~没有导出功能~~ ✅ 已解决

~~想把正文导出成 `.txt` / `.md`，现在只能手动复制。~~
~~批量导出、数据可携带格式（换平台时用）都还没有。~~

**已解决**：编辑页顶栏加了「导出」菜单，两个范围 × 两种格式，一共四路：

| 范围 | 格式 | 拿到的东西 |
| --- | --- | --- |
| 全书 | `.txt` | 一本书从头到尾，章节按顺序排好 |
| 全书 | `.md` | 同上，带 `#` 标题层级，适合发到支持 Markdown 的地方 |
| 当前章节 | `.txt` | 只导你正打开的这一章 |
| 当前章节 | `.md` | 同上 |

导出前会**先保存一次**——有没保存的改动也不会丢；保存失败（比如版本冲突）就不下载，
不会给你一份旧稿。

**还没做的**：一次导出多本作品（现在一次一本）。

### 8. 版本历史没有差异对比

只能看每个版本的**整篇全文**，不能"高亮出这一版比上一版改了哪几句"。

**计划**：接 diff 库做逐句对比。

### 9. AI 修改只能整篇采用，不能按句采用

润色结果是整篇的，四个动作（采用 / 替换 / 复制 / 放弃）都是对整篇作用。
没有"这句话改得好，那句我不同意"的逐条选择。

**计划**：按段落拆分结果 + 逐段接受。

### 10. 邮箱不能改

账号设置页的邮箱是只读的。
**为什么**：邮箱是账号唯一标识，作品、版本历史都挂在它下面，改邮箱牵扯数据归属。
要做应该是"验证新邮箱 → 迁移数据"的完整流程，不是普通表单。

### 11. 没有邮件通知

改密码、注销账号都不会发邮件提醒。
如果你怀疑账号被人动了，目前只能靠 `/account` 页和服务器日志。

### 12. 没有操作审计

谁在什么时候改了什么，服务端日志里只有错误级别的记录和几条关键动作
（`PASSWORD_CHANGED` / `ACCOUNT_DELETED` / `PROJECT_DELETED`）。
**做不成多用户协作前不着急**。

## ⚪ 工程债

### 13. 备份是手动的

`npm run db:backup` 要人记得跑。没有定时任务，没有自动上传到对象存储。
**上真服务器前至少配一个每日定时任务。**

### 14. 浏览器端到端脚本不是 CI 的一部分

`_p9/phase9.mjs`、`_p10/ui-flow.mjs` 这些是**手写的验收脚本**，
跑一次能全绿，但没有接进自动化流水线，每次发版要人记得跑。

**`npm test` / `npm run test:api` 是真的自动化测试**（70 + 48 项），
这两个应该每次改完都跑。

### 15. AI 用例的部分行为依赖假服务

`npm run test:api` 里的 AI 测试打的是**假 AI 服务**（`scripts/fake-ai-server.mjs`），
用正文里的魔术词（`[[UPSTREAM_500]]` 等）控制上游行为。

好处是**"上游挂了会怎样"这种平时复现不了的情况可以稳定测出来、且不花钱**；
代价是"真服务商的返回格式变了"这类问题它测不出来 —— 那要靠真 Key 手动验一次。

### 16. 密码只卡长度，不卡强度

只要求至少 8 位。没有"必须含大小写数字符号"，也没有比对已泄露密码库。

**为什么**：强行加复杂度规则的结果通常是大家都写 `Abc12345`，反而更弱。
长度才是最有效的因子。
**可以考虑**：接一个"这个密码是否已泄露"的查询接口。

### 17. AI 用量记账失败不重试

记账失败只写一条 warn 日志就放过（**这是刻意的**：已经生成好的润色稿必须交给用户，
不能因为记账失败把结果吞掉）。极端情况下会导致用量统计少记 ——
**不影响用户，但影响成本核算的准确性**。

### 18. 本机开发环境的一个怪现象

在这台机器的沙箱环境里跑 `npm run build`，**产物是完整可用的，
但进程退出码会是 1**（构建收尾的清理动作被环境的文件删除保护拦下）。
这不是代码问题：换一台普通机器、或换一个新会话跑，退出码就是 0。

判断产物好不好用这个方法：`.next/BUILD_ID` 存在 + `npm run serve` 起得来 + `/api/health` 返回 200。

### 19. Prisma 工具链挂着 3 条 high 级依赖告警

`npm audit` 报 3 条 high：`prisma`、`@prisma/config`、`deepmerge-ts`。
三条是同一根链，`fixAvailable` 指向 `prisma@6.12.0` 且标记为跨主版本（`isSemVerMajor`）。

**为什么不动**：这三个包只在**开发 / 构建期**使用，不进运行时、
不处理用户输入、不参与任何 HTTP 请求链。所谓"修复"是把 Prisma 降一个小版本，
收益不明而风险实在（要重新 `prisma generate` + 重跑全部迁移 + 重建）。
卸载掉两个无关依赖后重跑，仍是同样这 3 条 —— 说明与项目自己的依赖选择无关。

**计划**：跟着下一个大版本的依赖升级窗口一起处理（届时配套跑
`prisma generate` / `tsc --noEmit` / `lint` / `test` / `build` 全套）。

### 20. 测试文件里有一条未使用变量的 lint 警告

`tests/api/account.test.ts:38` —— `'other' is assigned a value but never used`。

不是 error，不影响构建，只出现在测试文件里。留着是因为修它要重跑一轮接口测试，
而这轮已经在第十阶段验收里跑过了（70/70 通过），不想在同一次验收里引入新变动。

**计划**：下次动测试文件时顺手删掉。

### 21. 「生产环境」这一环还没真正跑过

第十阶段的最终发布确认清单里，**第 1 项（生产数据库已备份）和第 2 项（生产迁移已验证）
是带条件的** —— 因为这台开发机上没有生产环境。

等价验证已经做过：用生产用的那条命令 **`prisma migrate deploy`**（不是 `migrate dev`，
dev 版会在结构漂移时想重置数据库）在一个从零建的空库上跑完 7 个迁移，exit=0，
第十阶段的两个验收脚本都是这么起库的。

**真部署时必须补做**：在预发库上跑一次迁移、备份一次、跑一次 `npm run preflight`。

## 附：怎么用这份清单

- **别人问"能导出吗"** → 能，第 7 条，编辑页顶栏「导出」（全书 / 当前章，txt / md）
- **收到"我密码忘了"** → 第 3 条，暂时只能手动处理
- **打算加机器 / 上负载均衡** → 先看第 4 条，不换 Redis 限流会失效
- **数据库文件变大到担心** → 第 2 条，备份后清理历史版本
- **发版前** → 第 14 条，记得手动跑那两个脚本（`npm test` / `npm run test:api`）
- **安全扫描报了 high** → 第 19 条，是 Prisma 工具链，已评估，不用慌
- **`npm run build` 退出码不是 0** → 第 18 条，本机沙箱的怪现象，先按那三条判断产物好不好
- **准备上线** → 第 21 条，先去预发库把迁移、备份、自检各跑一遍
