### 1.2 按用户能摸到的功能列（这才是真正「完成了什么」）

**账号与登录**
- 邮箱 + 密码注册、登录、退出登录
- 密码哈希存储（bcrypt，12 轮），库里搜不到明文
- 改昵称、改密码（改完所有设备强制重新登录）、注销账号（连同全部数据级联删除）
- 账号设置页能看到自己的数据概况（作品数 / 章节数 / 版本数 / AI 调用次数）

**作品管理**
- 作品列表（分页）、新建作品（自动带第一章）、作品卡片显示章节数
- 作品设置：作品名 / 简介 / 类型 / 风格档案（语气、叙事视角、句式风格）
- 删除作品（「危险区」，要手打作品名 + 系统二次确认才给删）
- 作品转移命令（`npm run works:move -- 邮箱`，把作品转给别的账号）

**写作编辑器（三栏）**
- 左栏章节列表：新建 / 切换 / 删除（删完自动补齐章节序号）
- 中栏编辑器：标题 + 正文、实时字数、自动保存（停笔 1.2 秒）、手动保存（按钮 / Ctrl+S）
- 保存状态灯：`已同步` → `保存中…` → `已保存 HH:MM:SS` / `保存失败`
- 切章前强制落盘、关页面用 keepalive 兜底 —— **不会因为切章或刷新丢字**
- 冲突保护：别人同时改了同一章会提示冲突，只给两条路（刷新取最新版 / 用我的内容覆盖）
- 无障碍：读屏能识别当前章、状态变化用 `aria-live` 播报、表单有真 label

**AI 功能（DeepSeek）**
- 文本诊断：按「重要 / 建议关注 / 轻微」三级给问题清单，每条带原因
- 轻度润色：生成修改稿，**先显示为待确认**，四个按钮自选 —— 「采用结果」(写进正文并保存) / 「替换当前内容」(只换字不保存) / 「复制结果」/ 「放弃结果」
- 绝不自动覆盖正文；AI 上下文含作品名 / 类型 / 简介 / 语气 / 视角 / 句式六项
- 每日 30 次额度、每分钟 10 次限流，面板上直接显示「今天还剩几次」
- AI 用量台账（含成功/失败、耗时、错误码），额度只算成功调用

**版本历史**
- 每次保存自动留档，列表分页加载（不全量拉）、点开才取全文
- 一键恢复到任意历史版本，恢复前会明确提示「当前正文不会丢，会作为新版本留下」

**数据安全与隐私**
- 所有业务接口都要登录 + 归属校验，越权一律 403/404，不返回真实数据
- 删除操作都有明确「不可恢复」提示；删除后不留孤儿数据（已直接查库验证）
- 全项目 `dangerouslySetInnerHTML` 0 处，正文里的 HTML 原样当纯文本显示

**运维（给老板用的）**
- 四条命令：`ops:daily`（日常巡检）/ `ops:db`（数据库体检）/ `ops:ai`（AI 用量报表）/ `ops:release`（发布流水线）
- 上线前自检 `preflight`、数据库备份 `db:backup`、恢复演练 `db:restore-drill`

| **日常启动**（已构建过） | `npm run serve` | 约 3 秒起来，端口固定 **3001** |
| **改了代码后启动** | `npm run app` | 构建 + 启动一步到位，要 2 分钟左右 |
| **停服务** | 在运行窗口按 `Ctrl + C`，或直接关掉那个黑窗口 | |

| 初始化数据库 | `npm run db:deploy` （空库时）或 `npm run db:migrate` | |
| 灌演示数据 | `npm run db:seed` | 可重复执行，不会覆盖已填内容 |

**本机两个特殊约定（不是代码问题）**：

1. **端口是 3001，不是 3000** —— 3000 被本机另一个常驻服务占着。
2. **不要用 `npm run dev`** —— 这台机器的开发模式热更新握手有毛病，页面会永远停在转圈。**一律用 `npm run serve` / `npm run app`**；改完代码要重新构建才生效。

> **服务会不会自己停？** 用 `start-moyu.bat` 或你自己在终端跑的 `npm run serve`，
> 只要你不停它就一直在。**但如果是由别人（或自动化）在会话里临时拉起来的服务，
> 那个进程可能会被回收** —— 表现为页面突然打不开。这时双击 `start-moyu.bat` 即可恢复，
> 数据不会丢（都在 `prisma/dev.db` 里）。

### 9.2 应用自己的错误日志怎么打

- 统一走 `src/lib/log.ts`，输出**结构化 JSON** 到进程 stdout，格式是「错误编号 + 上下文（userId / projectId / status / durationMs）」
- 错误编号是白名单制，含义对照表在 `docs/错误代码说明.md`
- 想接 Sentry 之类的服务，**只需要改 `log.ts` 里的那一个函数**

### 9.3 真部署后该去哪看

| 要看什么 | 去哪 |
| --- | --- |
| 构建日志 | 部署平台的项目页 → Deployments → 某次部署的 Build Logs |
| 运行日志 | 平台的 Runtime Logs / Function Logs |
| 应用是否健康 | 浏览器或 curl 打 `https://你的域名/api/health`（503 就是不健康） |
| 迁移是否执行 | 平台日志里搜 `migrate deploy`，或本地跑 `npx prisma migrate status`（连生产库） |
| 有没有持续 500 | `npm run ops:daily`（会拉可用性、健康检查、错误趋势、AI 失败率） |
| AI 有没有大量失败 | `npm run ops:ai`（失败率 / 限流次数 / 平均耗时 / 费用估算） |

## 10. 回滚方法

完整版在 `docs/回滚方案.md`，这里给可执行的部分。

### 10.1 铁律（发版前必做）

```bash
npm run db:backup      # 迁移之前先备份，这是回滚的保险
```

### 10.2 代码回滚

| 情况 | 怎么做 |
| --- | --- |
| 有 Git 仓库时（推荐，但目前还没建） | `git checkout v上一个版本` → `npm ci --legacy-peer-deps` → `npm run build` → 重启 |
| 现在（还没 Git） | 用上一次的构建产物目录换回来，或直接把代码改回上一版 → `npm run build` → 重启 |

重启命令：停掉旧进程 → `npm run serve`。回滚后**必须**跑一次 `curl http://127.0.0.1:3001/api/health` 确认 200。

### 10.3 数据库回滚

- **本次 `1.0.0-rc.2` 只加了 3 个字段（`ok` / `durationMs` / `errorCode`），不删不改旧数据 → 代码回滚不需要动数据库**
- 真要恢复数据：按 `docs/备份与恢复说明.md` 用 `backups/` 里的备份文件恢复（恢复演练跑过 19 项全通过，命令 `npm run db:restore-drill`）
- **数据回滚的代价**：备份之后写进去的内容会丢，所以「迁移前先备份」和「出事后尽快决定」都很重要

### 10.4 回滚决策参考

| 症状 | 第一反应 |
| --- | --- |
| 页面打不开 / 大量 500 | 先回滚代码（最快恢复） |
| 数据错乱 / 写到一半失败 | 先停服务，别再写；评估是否要恢复备份 |
| 只有某个新功能不好使 | 不急回滚，先按 `docs/已知问题.md` 判断是否可接受 |
