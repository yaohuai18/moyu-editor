# 运维手册

> 这份手册回答一个问题：**网站上线之后，每天/每周/出事的时候该做什么。**
> 所有命令都在项目根目录跑。看不到中文输出时，去 `ops-reports/` 里找刚生成的报告文件。

## 一、日常三件套

| 频率 | 命令 | 看什么 |
| --- | --- | --- |
| 每天 | `npm run ops:daily` | 应用活着没、健康检查、登录墙、保存链路、AI 故障趋势 |
| 每周 | `npm run ops:db` | 库完整性、容量、索引、孤立数据、迁移状态、备份新鲜度 |
| 每周 | `npm run ops:ai` | 每日调用量、失败率、耗时、费用估算、高频用户 |

三条命令都是**只读**的（`ops:release` 的自动备份除外），跑多少次都不影响用户数据。

报告会同时打到屏幕和 `ops-reports/` 目录：

- `daily-20260926-010018.txt` 这种文件名 = 哪条命令、什么时间跑的
- 每份报告结尾有汇总：**必须处理 0** 才算过关；有「提醒」看一眼就行

**`ops:daily` 的一个设计决定**：应用没启动不算故障（标「未启动」、跳过应用侧检查、退出码 0）。
开发机上晚上看一眼数据时经常是这种情况。「服务该开而没开」由部署平台监控，不归巡检管。

## 二、巡检报告怎么读

每份报告的条目分五级：

- `[ok]` 通过
- `[warn]` 提醒 —— 值得看一眼，不拦你发版
- `[FAIL]` 必须处理 —— 退出码非 0，发布流水线会被它拦下
- `[info]` 说明 —— 只是陈述事实（比如「这段时间没有 AI 调用」）
- `[skip]` 跳过 —— 前置条件没满足（比如探测账号没登上）

## 三、故障响应对照表

按「用户看到的症状」查。先跑 `npm run ops:daily`，大部分问题它会直接指出来。

| 症状 | 第一反应 | 深入排查 |
| --- | --- | --- |
| 网站打不开 / 一直转圈 | `curl http://127.0.0.1:3001/api/health` | 返回 503 → 看第 4 节；连不上 → 进程挂了，先 `npm run serve` 拉起来再看日志 |
| 所有人登录都失败 | 看 `/api/health` 的 `issues` | 数据库一项 error → 数据库问题；正常 → 看 [错误代码说明](错误代码说明.md) 里的 INVALID_CREDENTIALS 是不是突然变多（可能有人在撞库） |
| 保存一直失败 / 报「保存失败」 | `npm run ops:db` | 看「完整性」和「孤立数据」两节；都正常 → 可能是磁盘满了（SQLite 写不了） |
| AI 全部报错 | `npm run ops:ai` | 看「失败明细」：`AI_UPSTREAM_REJECTED` = Key 失效或欠费（去上游平台看）；`AI_TIMEOUT` 大增 = 上游慢，等或换模型 |
| 个别用户 AI 报错 | `npm run ops:ai` 看失败明细 | 只有一个用户失败 → 多半是他自己网络/内容超长；全站都在失败 → 上游问题 |
| 数据库文件锁住 / 报 SQLITE_BUSY | 停掉多余实例 | `netstat -ano | findstr 3001` 有两个 PID 在听 = 起了两份服务，杀掉旧的 |
| 页面样式错乱 / 白屏 | 浏览器 Ctrl+Shift+R 强刷 | 还不行 → 上次构建没成功就 restart 了，重新 `npm run build` |

**处理任何故障前的一条铁律：先 `npm run db:backup` 再动手。**
回滚靠备份，动手之前没有备份就没有退路。

## 四、健康检查返回 503 怎么办

`/api/health` 返回 503 只有两种原因，body 里会写明：

1. `database: "error"` —— 数据库连不上。看 `.env` 的 `DATABASE_URL` 指的文件在不在、
   磁盘满没满、有没有别的进程锁着库。
2. `issues` 里有 `level: "fatal"` 的环境变量问题 —— 按提示补 `.env` 然后**重启**
   （`.env` 只在启动时读一次，改完不重启等于没改）。

## 五、发布流程

完整流程一条命令：

```
npm run ops:release
```

它会依次跑「lint → 类型检查 → 单元测试 → 生产构建 → 接口测试」五连，
然后查迁移状态、确认备份新鲜（超过 24 小时会自动先备一份），
最后打印部署九步清单。**五连不全绿不要发版。**

九步清单（手册版，命令版看脚本输出）：

1. 改 `package.json` 的 version，更新 [发布记录](发布记录.md)
2. 代码入库打标签
3. 服务器拉代码 + 装依赖
4. **备份先行**（迁移之前做，这是回滚的保险）
5. `npm run db:deploy` 应用迁移
6. `npm run build`
7. 停旧进程、起新进程
8. 健康检查应返回 200
9. 冒烟：登录 → 建作品 → 写两个字看状态灯 → `npm run ops:daily`

发完发现不对 → 直接看 [回滚方案](回滚方案.md)，别现场发明流程。

## 六、探测账号

`ops:daily` 要登录一个账号来测保存链路，账号从 `.env` 读：

```
OPS_EMAIL=专用探测账号的邮箱
OPS_PASSWORD=这里填你的值
OPS_BASE_URL=http://127.0.0.1:3001   # 不配默认 3001
```

没配时用演示账号 `demo@moyu.local`。**上线删演示账号之前记得配**，
否则「登录/退出」和「保存链路」两项会一直显示提醒。

## 七、巡检脚本自己出问题时

- 报「数据库连不上」→ `.env` 的 `DATABASE_URL` 没配或文件被挪走了
- 报告文件写不出来 → `ops-reports/` 所在磁盘满了
- `ops:db` 的查询探针报「查不了」→ 库是全新的、一条数据都没有，属正常
