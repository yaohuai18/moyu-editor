# 数据库迁移说明

数据表结构不是手改的，而是**由 `prisma/schema.prisma` 生成迁移文件、再执行**。
这样做的好处是：结构变更有文件记录，任何一台机器都能重放出同样的库。

---

## 一、两种命令，别用错

| 命令 | 用在哪 | 行为 |
| --- | --- | --- |
| `npm run db:migrate` | **只在本地开发** | 改 `schema.prisma` 后跑它。它会对比结构、生成迁移文件、执行，必要时**会问你话**（比如"要重置数据库吗"） |
| `npm run db:deploy` | **生产只能用这个** | 只把已经存在的迁移文件按顺序执行完。不问话、不改 schema、不生成新文件 |

> ⚠️ 在生产上跑 `db:migrate` 是很危险的：需要交互时它会挂住，
> 而某些情况下它会提议**清空数据库**重来。生产永远只跑 `db:deploy`。

本地改完结构的完整流程：

```bash
# 1. 改 prisma/schema.prisma
# 2. 生成 + 应用迁移（名字写清楚改了什么）
npm run db:migrate -- --name add_something
# 3. 重新生成客户端类型（migrate 会自动做，手动跑也不亏）
npx prisma generate
# 4. 类型检查，确认代码跟得上新结构
npm run typecheck
```

| 7 | `20260925145945_add_revision_chars` | `Revision.chars`：版本字数。版本历史列表只读这一列，不再把每条版本的正文都读出来算字数 |

查看当前状态：

```bash
npx prisma migrate status
```

## 三、加过列之后要回填的（第 6、7 条）

`Revision.chars` 是后加的列，加列之前的历史版本都是 `0`。
新部署（空库）不用管；**如果是给一个已经有数据的库升级**，跑一次：

```bash
npm run db:backfill-chars
```

它会找出 `chars = 0` 但正文不为空的记录，算好字数补上。
可重复执行，不会重复处理。

`User.tokenVersion` 不用回填 —— 默认值 `0`，老 Cookie 里没有这一项也按 `0` 算，
所以这次升级**不会**把所有人踢下线。

## 四、哪些字段开过"结构手术"（改结构前先看这节）

- **`Chapter.version`**：加了"版本号只在真的写入时 +1，冲突时不加"的语义。
  回滚接口也 +1，否则另一个标签页能拿旧版本号把回滚覆盖掉。
- **级联删除**：`Project → Chapter → Revision / Character / StyleProfile`
  全部是 `onDelete: Cascade`；`User → Project` 也是。
  所以删账号 / 删作品不会留孤儿数据 —— **这个性质有测试守着**
  （`tests/api/account.test.ts` 里直接查库断言各表计数为 0）。
  `Revision.userId` 是 `SetNull`（删用户不删历史版本），
  但实际上那些版本已经随着章节被级联删掉了。

## 五、索引（为什么是这三个）

| 表 | 索引 | 它服务的查询 |
| --- | --- | --- |
| `Project` | `[userId, updatedAt]` | 首页「我的作品，按最近编辑倒序」 |
| `Chapter` | `[projectId, updatedAt]` | 章节列表 |
| `Revision` | `[chapterId, createdAt]` | 版本历史（某章、时间倒序） |
| `AiUsage` | `[userId, createdAt]` | 算「今天用了几次」 |
| `AiUsage` | `[createdAt]` | 全站用量统计 |

加索引的判据只有一个：**这条查询会在每次打开页面时跑**。
不满足这条的字段先不加 —— 索引不是免费的，每次写入都要维护它。

## 六、迁移能不能回滚

**应用版本可以直接退回上一版，数据库迁移不一定能安全逆向。**

- `ALTER TABLE ... ADD COLUMN`：退回旧版本时，多出来的列不影响旧代码运行
  → 一般可以只退回应用、不动表结构
- `DROP COLUMN` / 改数据类型 / 拆表：**旧代码读不了新结构，退了就起不来**
  → 必须先备份，并且准备好「向前兼容」的方案（比如先加新列、双写一段时间、
  确认没问题再删旧列）

规矩：**任何删除字段或改数据结构的迁移，上线前先跑 `npm run db:backup`。**
具体操作看 [回滚方案](回滚方案.md)。

## 七、`.env` 与库文件的位置

- 本地 SQLite 文件在 `prisma/dev.db`（`DATABASE_URL="file:./dev.db"`，
  相对路径是相对 `prisma/` 目录算的）
- 接口测试用的是另一个库 `prisma/test.db`，由 `scripts/api-test.mjs` 起独立实例连接。
  **测试数据不会写进开发库** —— 测试里有一条自检断言专门守这个：
  `DATABASE_URL` 必须包含 `test`，否则直接报错
- 备份文件默认放 `backups/`（已被 `.gitignore` 忽略，不进 Git）
