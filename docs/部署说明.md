# 部署说明（把网站放到真服务器上）

这一份是「从一台只有系统的新机器，到网站上能打开」的完整顺序。
每一步都会说明「为什么」，出问题时你就知道该往哪儿看。

---

## 〇、上线前必做的四件事

这四件不做完，别对外发链接。

| # | 做什么 | 为什么 |
| --- | --- | --- |
| 1 | 换掉泄露过的 AI Key | 聊天记录里出现过的 Key 等于已经公开，别人能拿去花你的钱 |
| 2 | 删掉或改掉演示账号 `demo@moyu.local` | 它的密码是写在文档里的（`moyu-demo-2026`），谁都能登 |
| 3 | 把 `AUTH_SECRET` 换成随机值 | 它是会话 Cookie 的加密密钥，用默认值等于会话可以被伪造 |
| 4 | 数据库换成 Postgres（多实例时） | SQLite 是单文件，多个实例读同一份文件会锁冲突 |

生成 `AUTH_SECRET`：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

把输出整段贴进环境变量即可。**换掉之后所有人要重新登录一次，这是正常的。**

## 一、服务器上要装什么

- **Node.js 22 或更高**（本项目在 22.22.2 上开发验证）
- **一个能跑常驻进程的方式**：systemd / pm2 / 容器，任选其一
- **HTTPS**：反代（Nginx / Caddy / 云厂商负载均衡）负责，应用本身只跑 HTTP

不需要装 Docker，也不需要装 Postgres —— 除非你要多实例部署（见第五节）。

## 二、第一次部署（照顺序做）

### 1. 拉代码

```bash
git clone <你的仓库地址> moyu-editor
cd moyu-editor
```

### 2. 装依赖

```bash
npm install
```

### 3. 写环境变量

在项目根目录建一个 `.env`（或者更推荐：在部署平台的环境变量页里逐条填）。
需要的变量和取值规则见 [环境变量说明](环境变量说明.md)。

### 4. 建表 / 更新表结构

```bash
npm run db:deploy
```

> ⚠️ 生产**只能**用 `db:deploy`。
> `npm run db:migrate`（= `prisma migrate dev`）会在需要时让你交互确认、
> 甚至提示重置数据库 —— 那是开发命令，在生产上跑等于把数据交出去赌。

### 5. 构建

```bash
npm run build
```

### 6. 起服务

```bash
npm run start -- --port 3000
```

`package.json` 里的脚本：

| 命令 | 干什么 |
| --- | --- |
| `npm run app` | 构建 + 起在 3001（本机自用） |
| `npm run build` | 只构建 |
| `npm run start` | 只起服务（默认 3000，可 `-- --port 8080` 改） |

### 7. 验一遍

```bash
curl -s http://127.0.0.1:3000/api/health
```

正常时看到：

```json
{"status":"ok","database":"ok","aiConfigured":true, ...}
```

- `status` 不是 `ok`（HTTP 503）→ 数据库或必要环境变量有问题，看 `issues` 字段
- `aiConfigured: false` → AI Key 没配好，网站能用但 AI 按钮会报 503

**健康检查接口是唯一的免登录接口**，它只回「哪个变量名有问题、什么性质」，
不回变量值、不回连接串、不回堆栈 —— 可以放心挂在公网给拨测用。

## 三、用 systemd 常驻（推荐）

`/etc/systemd/system/moyu.service`：

```ini
[Unit]
Description=Moyu Editor
After=network.target

[Service]
Type=simple
WorkingDirectory=/srv/moyu-editor
# 环境变量写在单独的文件里，权限设成 600（只有 root 能读）
EnvironmentFile=/srv/moyu-editor/.env
ExecStart=/usr/bin/node node_modules/next/dist/bin/next start --port 3000
Restart=always
RestartSec=5
User=moyu

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now moyu
sudo systemctl status moyu
```

**日志怎么看**：`journalctl -u moyu -f`
线上排查基本都从这儿开始（错误编号就在里面，见 [错误代码说明](错误代码说明.md)）。

## 四、反代与 HTTPS

Nginx 关键几行：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    # Auth.js 判断协议要用到这一行，漏了会登录不上
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

配好域名后，环境变量要做对应调整（二选一）：

- `AUTH_URL="https://你的域名"` ← 推荐，最明确
- 或继续用 `AUTH_TRUST_HOST="true"`

两个都不配，登录会报 `UntrustedHost`。

## 五、SQLite 还是 Postgres？

**现在用的 SQLite，因为它零安装。** 什么时候必须换：

- 网站跑在**两个及以上实例**（负载均衡、Serverless 多副本）
- 要接云数据库、要异地备份

换的时候只动两处：

1. `prisma/schema.prisma` 里 `datasource` 的 `provider` 改成 `"postgresql"`
2. `DATABASE_URL` 换成 Postgres 连接串

**业务代码一行都不用改。** 之后重跑 `npm run db:deploy`（如果是新库，
等于是从零建表，历史数据要另外迁）。

> ⚠️ 多实例还有一个坑：AI 的「每分钟 10 次」限流是**进程内内存计数**
> （`src/lib/rate-limit.ts`），多实例下每个实例各算各的，等于限流失效。
> 那时候要换 Redis，代码里已经标了位置。
> 每日 30 次额度不受影响 —— 它是查数据库算的。

## 六、每次发布的标准动作

```bash
git pull
npm install                 # 依赖有变化时
npm run db:backup           # 先备份，再动数据库
npm run db:deploy           # 应用新迁移
npm run build
# 重启服务
sudo systemctl restart moyu
curl -s http://127.0.0.1:3000/api/health
```

发布完在 [发布记录](发布记录.md) 里补一行。出了问题看 [回滚方案](回滚方案.md)。

## 七、上线后第一天盯什么

| 盯什么 | 怎么盯 | 什么算不正常 |
| --- | --- | --- |
| 登录失败 | 日志搜 `LOGIN_FAILED` | 成片出现 = 可能有人在撞库 |
| 数据库 | 搜 `DATABASE_ERROR` | `P1001` / `P1008` = 连不上或连接池满 |
| AI | 搜 `AI_PROVIDER_ERROR` | 集中 `401` = Key 失效；集中 `429` = 上游限流 |
| AI 慢 | 看日志里的 `durationMs` | 明显变长 = 上游在排队 |
| 刷接口 | 搜 `RATE_LIMITED` | 同一个人反复出现 = 有人在刷 |
| 500 | 搜 `UNKNOWN_ERROR` | 任何一条都要当天看 |
| 站点活着 | 外部拨测 `/api/health` | 返回 503 = 数据库或环境变量有问题 |

**出事的处理顺序**：先降级（把 AI Key 摘掉，网站照常能写字）
→ 再查数据库连接 → 再看最近改了什么 → 回滚 → 最后才查异常请求。
