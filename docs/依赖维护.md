# 依赖维护

> 这份文档回答：**什么时候该升级依赖、怎么升才不出事、审计报漏洞怎么办。**
> 现在的 7 个运行依赖 + 12 个开发依赖是清理过的，没有「装了没用」的包。

## 一、原则

1. **不盲目升主版本**（`4.x → 5.x`）。主版本 = 作者明确说了「可能不兼容」。
2. **补丁和小版本**（`4.6.5 → 4.6.6`、`4.6 → 4.7`）风险小，可以升。
3. 预发布版本（带 `-beta`、`-rc`）**不主动升**，除非当前版本出了确凿的问题。
4. 每次升级后必须跑完整验证，见第四节。

## 二、例行检查（建议每月一次）

```bash
npm outdated          # 哪些包有新版本
npm audit             # 有没有已知漏洞
```

**2026-09-26 的检查结论**（记录在案，别重复排查）：

- `npm outdated`：所有可升级项全部是**跨主版本或预发布**
  （Prisma 6→7/8-rc、TypeScript 5→7、ESLint 9→10、next-auth beta→4.24 实为降级）
  —— 按原则第 1、3 条，**一个都不动**
- `npm audit`：3 条 high，全部来自 Prisma 工具链（`prisma` / `@prisma/config` /
  `deepmerge-ts`），只在开发构建期加载，不进运行时、不接触用户输入；
  官方修复方案是把 Prisma 降一个小版本，风险大于收益 → **记录在
  [已知问题](已知问题.md)，等 Prisma 出正常的 6.x 补丁再升**

## 三、升级单个依赖的标准动作

以升级 `zod` 为例：

```bash
npm install zod@^4.7.0 --legacy-peer-deps
```

⚠️ 这台机器必须带 `--legacy-peer-deps`，否则 npm 自己会崩（已知问题）。

如果动了 Prisma（`prisma` 或 `@prisma/client` 任何一个）：

```bash
npm install prisma@6 @prisma/client@6 --legacy-peer-deps
node node_modules/prisma/build/index.js generate
```

**Prisma 两个包必须同版本**，且本机只能用 6.x（registry 的 latest 和
`@prisma/client` 的 latest 大版本对不上）。

## 四、升级后的验证（顺序就是依赖顺序）

```bash
npm run lint          # 0 error
npm run typecheck     # 0 error
npm test              # 单元 48 项
npm run build         # 生产构建
npm run test:api      # 接口 70 项（用的是刚构建的产物，所以排在 build 后面）
```

嫌手动麻烦就直接 `npm run ops:release`，五连检查就是这套东西。

## 五、删依赖

删之前先确认真的没人用：

```bash
# 在 src/ 和 scripts/ 里搜一下包名
```

确认没有引用再删：

```bash
npm uninstall 包名 --legacy-peer-deps
```

删完照第四节跑一遍验证。（第十阶段就是这样删掉 `lucide-react` 和
`@auth/prisma-adapter` 的——装了但代码里一次都没用。）

## 六、锁文件

- `package-lock.json` 锁住每个依赖的**确切版本**，必须进 git
- 服务器上用 `npm ci`（严格按锁文件装），不用 `npm install`（会自己挑版本）
- 手滑把锁文件改乱了：`git checkout -- package-lock.json` 恢复
