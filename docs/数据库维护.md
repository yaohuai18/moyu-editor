# 数据库维护

> 这份文档回答：**库会不会坏、会不会满、满了/慢了怎么办、什么时候该搬家。**
> 体检命令：`npm run ops:db`（只读，随时可跑），报告落在 `ops-reports/db-*.txt`。

## 一、现状

- 数据库是 **SQLite**（单文件，`prisma/dev.db`），单机部署完全够用
- 8 个迁移全部应用（`ops:db` 第 6 节会核对目录和库里的记录是否一致）
- 为什么不是 PostgreSQL：这台机器上没装 Postgres 也没有 Docker。
  业务代码通过 Prisma 访问数据库，**搬去 Postgres 只改两处**：
  `schema.prisma` 的 provider 和 `.env` 的 `DATABASE_URL`，别的都不用动。

## 二、`ops:db` 七节各看什么

| 节 | 看什么 | 什么时候要行动 |
| --- | --- | --- |
| 完整性 | `quick_check` 是不是 ok | 不是 ok = 库文件损坏，立即停止写入，从备份恢复 |
| 容量 | 库文件 / WAL 大小 | 见第四节 |
| 行数 | 各表条数 | 版本表疯长时做清理（第五节） |
| 关键查询 | 平均延迟 + 是否走索引 | 出现「整表扫描」警告 = 索引丢了或查询改坏了 |
| 孤立数据 | 应该全是 0 | 出现非 0 = 删号没删干净，按 [备份与恢复说明](备份与恢复说明.md) 处理 |
| 迁移状态 | 待应用 / 跑挂的迁移 | 有待应用 = 部署前漏了 `npm run db:deploy` |
| 备份 | 最新一份的年龄 | 超 24 小时会提醒；生产库每天一备是底线 |

## 三、WAL 文件是什么

`dev.db-wal` 是 SQLite 的「先记小本再誊大账」机制，正常会自动合并。
**一直变大不合并**说明有长事务卡着或上次异常退出。

处理：跑一次 `npm run db:backup` —— 备份脚本会先做 checkpoint 再复制，
WAL 就合并回主库了。跑完 WAL 还在涨，说明有进程锁着库没放（两个服务实例最常见）。

## 四、容量：多大算大

参考值（单文件 SQLite）：

- **< 100 MB**：什么都不用管
- **100 MB ~ 1 GB**：开始关注版本表的清理（第五节）
- **> 1 GB**：认真考虑搬 Postgres + 多实例部署

`ops:db` 会显示页统计和 WAL 大小；看单表占用最直接的办法是
`npm run db:studio`（可视化）里看 Revision 表行数。

## 五、版本表清理（最容易疯长的表）

每次保存都会留一条 `Revision`。一个活跃作者一天存 50 次 = 一天 50 条。
**建议策略（还欠着没做自动化，目前手动）：**

1. `ops:db` 看「平均每章版本记录」：超过 200 就该清了
2. 清理原则：**每章保留最近 50 条 + 当天的全部**，更老的删掉
3. 删之前先 `npm run db:backup`
4. 清理 SQL 模板（按章保留最近 50 条，先 SELECT 确认再改 DELETE）：

```sql
-- 预览要删的
SELECT id, chapterId, createdAt FROM Revision
WHERE id NOT IN (
  SELECT id FROM Revision r2
  WHERE r2.chapterId = Revision.chapterId
  ORDER BY createdAt DESC LIMIT 50
);

-- 确认数量合理后再执行删除（同样的 WHERE）
```

> 这段 SQL 不在脚本里自动化，是因为删数据必须有人看一眼数量再点头。

## 六、备份保留策略

- `npm run db:backup` 每次生成 `backups/moyu-时间戳.db`
- **建议保留**：最近 7 天的每日一份 + 每月一号那份长期留
- 手动清理老备份（直接在 `backups/` 里删旧文件即可，不影响任何运行中的东西）
- 恢复演练：`npm run db:restore-drill`（19 项检查，全程不碰真库）

## 七、什么情况必须立即搬家到 PostgreSQL

出现以下任何一条，就别再用 SQLite 硬扛：

1. 需要两台以上机器同时跑服务（SQLite 文件没法多机共享）
2. 库超过几个 GB 且持续增长
3. 经常出现 `SQLITE_BUSY`（并发写入顶到天花板）

搬家步骤（半天工作量）：改 provider → 改 `DATABASE_URL` →
`npm run db:deploy` 建表 → 用备份文件导数据 → `ops:db` 全绿 →
`ops:daily` 全绿。业务代码零改动，这是当初选 Prisma 的原因。
