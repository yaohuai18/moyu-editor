## 本次发布详情（`1.0.0-rc.2` · 第十一阶段）

**时间**：2026-09-26

**数据库迁移**：`add_ai_usage_monitoring`（`AiUsage` 表加 `ok` / `durationMs` / `errorCode`
三个可空列，只加不改不删，回退安全）。

**主要改动**

1. **AI 台账开始记失败**：失败 / 被限流的调用也落一条 `ok=false` 的记录
   （带错误编号和耗时），失败率、限流次数从此可查；**额度仍只认成功**，
   失败不扣用户次数
2. **四条运维命令**：`ops:daily`（日常巡检，应用没开不算故障）、
   `ops:db`（数据库体检七节）、`ops:ai`（AI 报表七节，含费用估算）、
   `ops:release`（发布流水线：五连检查 + 迁移核对 + 备份不足自动补 + 部署九步清单）
3. **运维文档七份**：运维手册、数据库维护、依赖维护、AI用量监控、
   用户反馈处理、产品迭代优先级、当前版本档案（索引见 `docs/README.md`）
4. `.env.example` 补运维可选项（`OPS_EMAIL` / `OPS_PASSWORD` / `AI_COST_*`）

**验证情况**

- `npm run ops:release` 五连全绿：lint 0 error / tsc 0 error / 单元 65/65 /
  构建退出码 0 / 接口 70/70；迁移 8/8 已应用
- `ops:daily`：应用在跑时 10 项全过；应用没跑时正确跳过且退出码 0
- `ops:db`：quick_check ok、无孤立数据、关键查询全部走索引、迁移 8/8
- `ops:ai`：空态和有数据两种情况都正常出报告

## 发布详情（`1.0.0-rc.1` · 第十阶段）

**时间**：2026-09-25

**数据库迁移**：无新增。
（第九阶段的三个迁移已经包含在这次发布里，见上表。）

**主要改动**

1. **账号自己的事能自己做了**
   - 新增 `/account` 账号设置页：改昵称、改密码、注销账号
   - 改密码会让**所有设备（含当前浏览器）的登录态立刻失效**
     （`User.tokenVersion` 会话代次机制）
   - 注销账号会级联删掉作品、章节、版本历史、人物卡、风格档案、AI 用量台账
2. **删除入口补齐**
   - 作品设置页新增「危险区」：要手动输入作品名才能删，删前明确告知不可恢复
   - 编辑页章节列表每条后面加了删除按钮（带确认，会连带删掉该章的版本历史）
   - 章节删除后自动补齐顺序号，不留空档
3. **列表改成分页，长内容不再一次性拉全**
   - `GET /api/projects?limit=&offset=`，首页首屏 24 部 + 「加载更多」
   - 版本历史列表**只回摘要**（时间/原因/字数），点开单条才取全文
   - `Revision.chars` 让列表查询完全不读正文列
4. **编辑器状态与 AI 结果处理**
   - 状态灯补全：未修改 / 有改动待保存 / 保存中 / 已保存 HH:MM:SS / 保存失败 / 恢复中；AI 状态独立一格（处理中 / 已完成 / 失败）
   - 润色结果四个动作：**采用结果 / 替换当前内容 / 复制结果 / 放弃结果**
   - **AI 结果永远不会自动覆盖正文**；等待期间正文被改过、或切换了章节，会明确提示甚至作废
   - 关页面不再可能丢字（按需刷新已改为带版本号，冲突时不误发）
5. **移动端与可访问性**
   - 编辑页顶栏允许换行（窄屏不再把按钮挤到点不着）
   - 弹窗、按钮、状态全部补齐 `aria-*`：状态灯 `role="status"`、错误 `role="alert"`、当前章节 `aria-current`、图标按钮 `aria-label`
   - 错误提示**不只靠颜色**：一律带 ⚠ 前缀 + 明确文字
   - 对比度不足的灰字（`slate-300/400`）统一提到 `slate-500` 以上
6. **文档与发布准备**
   - 新增 `docs/` 十份文档（部署、环境变量、迁移、API、错误码、备份恢复、回滚、发布记录、隐私政策、用户协议、已知问题）
   - 版本号从 `0.1.0` 提到 `1.0.0-rc.1`
