## 为什么这块最值得先验

`AGENTS.md` 记着一条「已修但设计决策要保留」：

> 切章前必须先检查保存结果，否则保存失败照样切章，用户正文直接丢失。

这是编辑器里**唯一会真的让用户丢字**的地方，而且只在「界面上的操作顺序」里才暴露——类型检查、96 个单测、87 个接口测试都碰不到。这就是 verify skill 存在的理由。

## 二、保护 B：保存失败时取消切章（实测 ✅ 核心）

**制造失败**（不动代码、不改 .env，在页面里拦 fetch）：

```js
if (!window.__origFetch) window.__origFetch = window.fetch;
window.fetch = function(...args) {
  const u = typeof args[0] === 'string' ? args[0] : (args[0]?.url || '');
  const m = ((args[1]?.method) || 'GET').toUpperCase();
  if (u.includes('/api/chapters/') && m !== 'GET') {
    return Promise.reject(new TypeError('Failed to fetch (simulated offline)'));
  }
  return window.__origFetch.apply(this, args);
};
```

然后打字 → 等 3 秒 → 点另一章。

**实测结果**：

| 检查点 | 实际 |
|---|---|
| 状态灯 | `保存失败，请检查网络` |
| 点第 1 章后当前章 | **仍是第 2 章**（没切走） |
| 正文 | **42 字原样保留** |
| 提示文案 | `当前章节没有保存成功，已取消切换章节（避免丢字），请稍后再试` |

文案与源码 `editor-client.tsx:597` **一字不差**。

用完记得 `window.fetch = window.__origFetch` 还原。

## 三、保护 A：有 409 冲突时不许切章（实测 ✅）

制造 409（模拟另一台设备先保存了）：

1. 页面停在第 2 章，先 `GET /api/chapters/<cid>` 看 `version`（实测是 2）
2. 用接口带着这个 version 再存一次，把库推到 version 3：

```js
await fetch('/api/chapters/<cid>', {
  method: 'PATCH', credentials: 'include',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ content: '另一台设备写进来的内容。', version: 2 })
});
// 返回 200，库变 version: 3
```

3. 回页面打字 → 自动保存带的是旧 version 2 → 服务端 409

**实测结果**：

| 检查点 | 实际 |
|---|---|
| 状态灯 | `自动保存已暂停，你打的字还在编辑区里没丢。请选择：` |
| 冲突提示 | `内容已被更新。本章在别处（另一个标签页或设备）保存过，你这边看到的是旧版本，自动保存已暂停，你打的字还在编辑区里没丢。请选择：` |
| 两个按钮 | `刷新取最新版` / `用我的内容覆盖` |
| 点第 1 章 | **没切走**，仍在第 2 章，正文 21 字保留 |
| 拦截文案 | `本章存在未解决的冲突，请先在上方选择「刷新取最新版」或「用我的内容覆盖」，再切换章节` |

文案与 `editor-client.tsx:583` 一字不差。

**顺带验了出口**：点「刷新取最新版」→ 冲突提示消失，正文变成库里那一版（22 字的「另一台设备写进来的内容…」）。冲突解法是通的。

## 四、实测顺手挖到的一个真问题

制造保护 B 那次，界面显示 `保存失败，请检查网络`，**但刷新页面后库里其实是 42 字**——那次请求后来成功了。

这说明 **UI 状态双向都不可信**：说失败可能成功，说已保存也可能没落盘。所以 SKILL.md 的第一条铁律「界面说已保存不算证据，必须查库」不只是保守，是实测出来的必要性。

**验切章时，凡涉及「字有没有保住」的判断，一律以查库为准，不要看状态灯。**

## 五、失败对照表

| 现象 | 结论 | 严重度 |
|---|---|---|
| 切章后正文空白，切回来也空 | 保存没落库 / 加载挂了，**正文已丢** | 🔴 最高 |
| 切章后正文还是上一章的内容 | 章节 id 没换，加载没生效 | 🔴 高 |
| 冲突时仍能切走 | 保护 A 坏了 | 🔴 高 |
| 保存失败仍能切走 | 保护 B 坏了，**会丢字** | 🔴 最高 |
| 字数显示与实际不符 | `countWords` 或回填错了 | 🟡 中 |
| 切章后诊断/润色结果还在 | 该清没清（`editor-client.tsx:605` 本应清掉） | 🟡 中 |

## 六、复跑 checklist（3 分钟）

1. 建两个章节，第 1 章打 20 字，等 `已保存`
2. 切第 2 章 → 正文应为空
3. 打 20 字，等 `已保存`
4. 切回第 1 章 → 应看到第 1 章那 20 字
5. **查库**：两章 content 分别对，`version` 都 ≥ 1
6. 跑一次保护 B 的 fetch patch → 应被拦住并给出「已取消切换章节」
7. 还原 fetch

第 5 步不能省。
