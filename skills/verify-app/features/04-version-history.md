## 1. 版本自动生成（这条已实测）

保存成功后版本会自动生成，不需要手动操作。断言点：

```
版本历史
1 / 1 条
2026/11/21 12:01:18
编辑器保存 · 35 字
```

- 条数格式 `N / N 条`
- 每条显示时间 + `changeReason` + `N 字`
- 编辑页右侧面板，位置在「人物卡」下面

**改过章节接口 / 保存链路时，这一条必须验**：保存成功但没有新版本记录 = 版本历史坏了（用户丢了「回滚」这个救命功能）。

## 3. 恢复某版本

按钮文案：`恢复此版本`（执行中变 `恢复中…`，`editor-client.tsx:2061`）。

**它会弹 `window.confirm`**，文案是：

```
确定要恢复到 <时间> 这一版吗？

当前正文会被替换掉，但不会丢 —— 恢复前的内容会作为新版本留在历史里。
```

成功提示：

```
已恢复到 <时间> 那一版；恢复前的正文仍留在版本历史里，随时可以再退回去。
```

**断言三条**：

1. 正文变成那一版的内容；
2. 版本历史**多了一条**（不是替换）——恢复本身会写一个新版本，这样「退回去」永远可行；
3. 库里 `revisions` 计数 +1、`version` +1。

⚠️ **DSH 浏览器工具没有 dialog（confirm/alert）处理 API**。`browser_click` 点到恢复按钮时，confirm 可能被执行环境的默认行为自动取消或让页面挂住。两种应对：

- 如果页面正常继续 → 说明自动 accept 了，正常验；
- 如果卡住 / 没反应 → **不要重复点**，改用接口直接验：

```
POST /api/projects/<projectId>/revisions/<revisionId>/restore
```

带登录 Cookie，然后回到界面刷新看结果 + 查库。这条限制是真实的，报告里要写明用的是哪条路。

## 4. 删除章节（顺带记一笔）

确认文案：`确定删除「<章节名>」吗？\n\n这一章的正文和全部历史版本都会一起删掉，无法恢复。`

同样受 dialog 限制。删章节是**不可逆**操作，验证脚本里不要跑——除非专门在验删除，且用的是临时账号。
